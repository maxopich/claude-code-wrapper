# Safety and security

Reference detail lifted out of [`CLAUDE.md`](../CLAUDE.md). **Nothing under
`docs/` is auto-loaded** — see [`bus-architecture.md`](bus-architecture.md) for
the same note. Read this before touching `server/src/notifications/`,

`server/src/auth.ts`, `server/src/origin.ts`, or

The consultant-mode constraint itself, and the two limits on it, stay in
`CLAUDE.md` — they are what an agent reads and acts on. This page is why it is
shaped that way, plus the detect-and-contain layer sitting behind it.

## Why the consultant guardrail is advisory

The guardrail is advisory in the strict sense — the model interprets the prompt and nothing denies the tool call. `bus/guardrail.ts` classifies violations post-hoc so the operator sees them, and explains why enforcement is not wired: it would cover `Write`/`Edit`/`MultiEdit`/`NotebookEdit` only, while `Bash` and symlinked paths still escape.

## The mechanical brake: pause-on-dangerous

Operators also get a **mechanical** brake: an opt-in per-session **pause-on-dangerous** toggle. Cebab classifies every worker tool call `read`/`mutate`/`dangerous` (`shared/src/mutation.ts`, cross-platform — Unix shells + Windows cmd/PowerShell, matched case-insensitively); with the toggle on, a worker halts for operator approval at any `dangerous` command (`rm`, `sudo`, force-push, `curl|sh`, system/secret-path writes, `del`/`format`/`Remove-Item`/`reg delete`/`powershell -c`, …) via `applyPauseGate` / `releasePauseForMutation` in `bus/pause_gate.ts`, imported by both `orchestrator.ts` and `chain.ts`. It is **dangerous-only** by design: MCP tool calls and ordinary edits classify as `mutate` and run **free** — their guardrail is the MCP server's own permissions plus the hash-chained audit log, not a Cebab pause.

**The halt holds the agent's turn QUEUE, not just its turn (`Cebab-vie.13`).** The gate stops an agent by throwing out of the mutation tap, which kills the turn that issued the command — and for a long time that was all it did. The agent's turn queue stayed open, so the next delivery to it (a peer's `bus_send`, an orchestrator follow-up, a retry) started a fresh turn, and `decidePauseForMutation` waves an already-held agent through by design (`hasPendingPause` → `run`, so a second banner cannot stack). Its next dangerous command therefore ran **unapproved**, for as long as the operator left the banner un-actioned — un-gated rather than unlogged, since the row and the notification still fired after the fact. So `applyPauseGate` now also takes `AgentRunner.holdForMutation`, parking that agent's inbound deliveries behind the same never-resolving gate the operator's **pause** verb uses, and `continueThroughMutation` gives it back. The two are separate _holders_ of one gate: Continue does not lift a standing operator pause, and a pause expiry's `auto_resume` does not lift the hold on a worker still sitting at an unapproved `rm -rf`. The hold is in-memory, so `wireOrchestratorSession` reinstalls it for every `pending` mutation row at wire time — the R-B reseed Register B04 already does for the operator pause, for the same reason.

**The halt is a CLASS, and nothing downstream may re-decide it from the text (`Cebab-vie.14`).** `PausedForMutationError`'s message is `paused before ${row.summary}`, and for a `Bash` call that summary is the model's own command plus its `description`, verbatim — so the sentinel carries worker-written bytes. The runner's overload retry filter matched on `err.message` substrings (`API Error: 529`, `Overloaded`, …), which meant a worker could put `Overloaded` into either half and have **its own pause absorbed as a transient API failure**: the turn was retried, the replayed turn re-issued the command with a fresh `tool_use` id, and the gate stood down because `hasPendingPause` was true — the pause it was meant to respect is what made it true. `rm -rf /important` with the description `retry after Overloaded` was enough, and the operator's banner stayed on screen offering Continue for a command that had already run. `isTransientOverload` now asks `isBusControlSignal` before it looks at any string; `bus/errors.ts` names that category so a fourth sentinel has one obvious place to be added. `MutationNotRecordedError` had the same exposure on the fail-closed path, and `TurnStalledError` was immune only by accident of its text (it embeds the agent name).

**The halt covers the REST of the message, and the rest of the turn (`Cebab-vie.16`).** The tap runs per `tool_use` BLOCK, and the pause stops the turn by throwing out of it — which used to end the block loop too. So a worker that emitted `rm -rf /a` and `rm -rf /b` in one assistant message paused on the first and left Cebab's ledgers holding only that one: no `multi_agent_mutations` row for the second, no guardrail verdict, no dangerous-mutation notification and therefore no chained `safety_audit` row, and no banner entry — while whether the CLI had already dispatched it was a race. Two things in the tree described that sibling as a live caller before it was one: `decidePauseForMutation`'s own comment, and a green `pause_gate.integration.test.ts` case testing a call the runner never made. The runner now replays the dying message's remaining blocks through the same tap, **after** closing the subprocess — deliberately, because the throw plus that close is what may reap the process before the sibling is dispatched, and delaying it to write rows first can only lose that race more often. Killing is safety; recording is forensics.

**And the halted worker now dispatches nothing further**, which is enforcement rather than a record. `canUseTool` denies while the agent's gate carries the `'mutation'` holder — free and exact, since `applyPauseGate` installs that hold before the pending write, the sink and the throw. The `'mutation'` holder specifically, never `'operator'`: an operator **pause** is a turn-scheduling gate that deliberately does not touch the running turn (`Cebab-vie.2`), and the two holders share one gate, so membership would not have distinguished them. This is **measured, not reasoned** — `server/src/bus_pause_gate_smoke.ts` (2026-08-25) establishes that the callback is consulted for a worker's in-cwd `Bash` and in-cwd `Write` and that a deny there stops the command, while an in-cwd **Read** is resolved by the CLI and never reaches it. The bypassed class is reads; the gate only ever fires on `dangerous`; they do not overlap. Without that measurement the deny would have been decoration, which is the failure mode this whole section catalogues. What it does NOT fix is the FIRST dangerous command of a turn: no hold stands when its control request arrives, so `Cebab-vie.15`'s race is unchanged and the honest claim remains that the pause reliably stops the worker rather than that the triggering command never ran.

**What happens when the gate cannot do its job (`Cebab-aqd`).** The gate runs from the routers' mutation tap, _after_ the call is persisted to `multi_agent_mutations` — and the tap's `catch` used to log the failure and `return`, which is upstream of `applyPauseGate`. So a failed INSERT silently disarmed the brake and the `dangerous` command ran: fail-**open** on the operator's only mechanical control. It now fails **closed**. `shouldHaltUnrecordedMutation` (same module, so the two routers cannot drift) answers with the two facts that do not live in the unwritable table — the classifier's category and the session's toggle — and the tap throws `MutationNotRecordedError`. If even the session read fails, the answer is halt: an unknown gate state on a `dangerous` command resolves to caution.

That error is deliberately **not** a `PausedForMutationError`. Both routers' `deliver().catch` return quietly on that class, which is right for a real pause (the row and the banner are already persisted) and wrong here (neither exists — the operator would see an agent that simply stopped, with nothing to click). Falling through to `onWorkerFailed` instead reuses the recovery that already exists: a pending-retry slot, a `cebab → user kind=error` event carrying the reason, and Retry / Abandon, with the session left `running`. A **disarmed** gate or a `mutate` call still runs — an operator who turned the gate off chose that, and a failed write is no reason to revisit it.

## Safety subsystem (multi-agent controllability)

Behind the consultant-mode prompt and the pause-on-dangerous toggle (the _prevent_ layer) sits a bus-side _detect + contain_ layer, none of it described above:

- **Hash-chained audit log** (`server/src/notifications/safety_audit.ts` → SQLite `safety_audit`): append-only; each row's `hash_self` is SHA-256 over its canonical contents **and the previous row's `hash_self`**, so altering any row breaks the chain and `verifyChain()` (run on boot) flags the first mismatch. Every trust decision, mute/pause/kick, dangerous-mutation, and guardrail violation writes a row.
- **Dispatcher dual-write** (`server/src/notifications/dispatcher.ts`): the single operator-notification fan-out (`emit()`). A _safety_-class event writes its audit row **before** the WS notification is sent — if the audit append throws, the caller refuses to proceed (`audit_write_failed`). Safety events are never coalesced; operational ones coalesce by key within short windows.
- **Forensic snapshots** (`server/src/notifications/forensic_snapshot.ts` → `controllability_forensics`): on a single-agent **Stop** or a multi-agent **kick/auto-kick**, captures the last-N events, pending tool calls, the agent's recent mutations, and a shallow workdir hash, keyed to the triggering audit row. Best-effort — the audit row is the obligation, the snapshot a bonus.
- **Bus-install TOFU gate** (`server/src/bus/install_trust_gate.ts`): trust-on-first-use — the first time a project is installed into the bus the operator must approve; the decision persists (`projects.bus_trust_decision`), denials are logged, and the install blocks until decided.
- **Hook trust ledger** (`server/src/repo/hook_trust.ts` → migration 030 `hook_trust`): the record of the auto-executing project hooks this document and `CLAUDE.md` both warn about. Workers and chain participants run `settingSources: ['user', 'project', 'local']`, so a participant project's `SessionStart` / `PreToolUse` / `PostToolUse` / `Stop` hooks execute on **every hop** — and none of them passes through `canUseTool`, so none can be approved or denied. Identity is the tuple (project, hook kind, declaring settings file, command, args); rewriting a command produces a **new** row reported as `first_seen`, and `script_sha` catches the other case — command untouched, the file it points at rewritten. **Detection, not prevention**: it records what will run and reports what changed; it does not park the spawn. `hook_trust.ts`'s header says why prevention was left as a separate change rather than half-built.
- **MCP trust ledger** (`server/src/repo/mcp_trust.ts` → migration 016 `mcp_trust`, gated by `repo/mcp_trust_gate.ts`): trust-on-first-use for every MCP server a project declares, and unlike the hook ledger this one **is** prevention — `awaitMcpTrustDecisions` parks the spawn until the operator answers, and a denial is enforced on the spawn it gated (`settings.deniedMcpServers` plus `disallowedTools`), not merely logged. Identity took two widenings to become honest about what was approved, and the two are worth reading as a pair because each is invisible to the other: `Cebab-rxg` (038) added **command + args**, so rewriting `.mcp.json` under an approved server NAME re-gates as `declaration_changed`; `Cebab-1af` (039) added **`script_shas_json`**, so leaving the declaration alone and rewriting the file it runs re-gates as `script_changed`. That second one is the npm shape — nothing an operator would notice in a `git diff` of the config — and `binary_sha` never covered it, because it hashes the COMMAND and the command is `node`. Files are pinned by hashing every arg that names a readable file rather than by guessing which arg is "the script"; the reasoning, and why args are resolved by existence while the command is resolved by shape, is in `computeScriptShas`'s header. **No backfill**: a row decided before 039 pins nothing and prompts for nothing, because hashing what is on disk at upgrade time would record bytes nobody approved — and launder the swap if it had already happened.
- **The runaway brakes now write rows** (`Cebab-vie.17`). Two ceilings stop a bus run, and they measure different things: the **hop budget** counts the messages between agents, and the **per-hop turn cap** counts the model turns inside one of them — the latter did not exist at all, so one `bus_send` bought an unbounded agent turn while the single-agent path had been capped since Cluster F. Both now emit a safety notification and a hash-chained row through one shared module (`notifications/bus_limits.ts`, so the two byte-identical routers cannot drift): `hop_budget.exhausted` / `hop_budget_exhausted`, and `max_turns.hit` / `max_turns_exceeded` — deliberately the **same kind the single-agent cap hit writes**, with `payload.surface` splitting them, so one forensic query still answers "how often do turns hit the cap?" across both surfaces. Neither is in `HIGHEST_AUDIT_KINDS`; acknowledging them needs no typed reason.

  **One deliberate divergence from BE-1.** Every other safety emitter refuses to proceed when the audit append fails. The budget stop **tears the session down anyway** and logs, because here "proceed" _is_ the teardown — refusing it would leave a runaway session running because its audit row could not be written, failing open on the one control that function is. The emit also carries its own `try/catch`, because `dispatcher.emit`'s `persistNotification` sits outside `emit`'s own try and therefore THROWS rather than returning `ok: false` when the `notifications` table is unavailable. Both routers' `router_drop` suites pin the divergence by dropping each table in turn and asserting the teardown still lands.

  **A cap hit is a control signal, not a remote failure.** `MaxTurnsReachedError` is the fourth member of `isBusControlSignal` (`bus/errors.ts`): a cap Cebab chose is Cebab stopping the turn, so `isTransientOverload` answers `false` by class and the hop is never auto-retried — otherwise the overload loop wraps three more full-length attempts around the bound that was just added. `error_during_execution` deliberately stays a generic `Error`, because its literal message _is_ that retry trigger. The membership rule that `Cebab-vie.14` left as a comment asking the next author to remember is now derived from the source by `errors.control_signal_registry.test.ts`.

- **Operator controls — mute / pause / kick** (`server/src/ws/control_verbs.ts`, `pause_expiry.ts`): **mute** drops the agent's outbound bus messages (returning an _oracle_ white-lie "delivered" so it can't detect the drop); **pause** holds its turns behind an `auto_resume | auto_kick` expiry timer; **kick** one-way-drains it (drops both inbound and outbound). All three persist to `multi_agent_participants` columns and reseed on server restart (R-B).

  **And the browser is now told about them on attach (`Cebab-vie.6` / `Cebab-vie.4`).** That reseed sentence was true and covered only the server: `multi_agent_started` carried no control state at all, so every attach — a refresh, a second window, an R-B reconstruct, a reopen — handed the client an empty map while the mute mirror, the runner's pause gate and the expiry timer all stayed in force. The consequence is worse than a missing badge, because each control's UNDO is rendered from the state that had gone missing: no muted flag, no **Unmute** item; no live `pausedUntil`, no **Resume** item; and a kicked participant came back offering the full live menu. The operator could see the drops and the refusals (`already_in_state`, with a toast) and had no verb left that repaired any of it — for a pause set to `auto_kick`, the timer then kicked a worker they could no longer reach. `buildParticipantControlSnapshots` (`ws/participant_control_snapshot.ts`) is the single builder all three `multi_agent_started` sites call, reasons included: those live in the hash chain rather than on the participant row, so it performs the same recovery `reconstruct.ts` already does for a paused agent, and ships the STATE even when that lookup comes back empty.

  Two details are load-bearing. The wire field is **required**, unlike its additive-optional neighbours, because an absent optional field hydrates to an empty map — which is indistinguishable from "nothing is restrained", i.e. an emit site that forgot it would reproduce this exact defect invisibly; required makes the compiler the emit-site test. And an **expired `pausedUntil` ships verbatim**: whether a pause is still live is a `> Date.now()` comparison the client already makes in three places, and a second copy of that rule, evaluated once at attach against a clock the operator never sees, is how the two answers start to disagree.

- **A control action that cannot be written to the hash chain does not happen** (`Cebab-vie.3` / `Cebab-vie.7`). Every operator verb now appends its `safety_audit` row FIRST and applies only if that succeeded — the BE-1 order `recordTrustDecision` and the managed-file editor already use. It used to be the reverse, and the failure mode was not a broken trail but a false sentence: mute flipped the DB and the router mirror, the append threw, and the operator was told **"Mute refused"** while the agent was muted. Pause was worse — the never-resolving runner gate went in, the expiry timer did not (it is armed on `ok: true`), and no Resume affordance rendered, so the agent was stopped for the rest of the process. Register B12 had already recorded that no retry could repair it: the idempotency check WAS the write (`UPDATE … WHERE muted != ?`), so a second attempt matched zero rows and returned above the audit block. Idempotency is now decided by a read (`getControlState`), which is what lets the audit go first and what makes the retry work.

  Two consequences worth knowing before relying on this. **`unmute` and `resume` refuse too**: while the audit store is broken, an already-restrained agent stays restrained, and the escape hatch is **Stop**, which appends nothing to the chain and therefore still works when the chain is what is broken. `Cebab-vie.25` proposes giving Stop an audit row — if it does, that append must be best-effort or this door closes with it. And the **auto-kick** path (pause expiry) keeps the old order deliberately: there is no operator to refuse, and refusing would leave an expired pause neither resumed nor kicked.

  **None of the three stops the agent ACTING, and the reason picker now says so (`Cebab-vie.5`).** Every per-agent verb is a routing or scheduling filter at the bus; not one reaches the running turn. Mute is outbound-only — a single `mutedSet.has(ev.source)` read, with the deliver branches consulting nothing and `bus/runner.ts` holding no `mute` reference at all — so a muted agent keeps receiving, keeps being woken, and keeps running `Bash`/`Edit`/MCP. Pause gates the NEXT turn (`AgentRunner.pause` documents "current in-flight turn NOT cancelled"); kick is pinned to `mode: 'drain'` because the server answers `hard_kill_unsupported_v1`. The operator-facing consequence was the defect: the reason list offered **Runaway loop** and **Cost ceiling** beside a verb that stops neither, and its `forensics` entry read "freeze this agent to inspect its state without further mutation" — a capability no verb has, and on Mute and Pause a doubly wrong one, since the forensic BUNDLE is kick-only (`captureKickForensics`).

  The vocabulary now lives once, in `web/src/components/agentControl/controlReasons.ts` — it was three inlined copies whose own comment argued they were identical, and Kick's `topology_repair` help had already drifted. **It is deliberately NOT filtered per verb.** "I muted it because spend was climbing" is a true and useful `safety_audit` record even though mute does not reduce spend, so dropping reasons would destroy forensic information to fix a copy bug; a per-verb `caveat` corrects the inference instead, and a per-verb `VERB_LIMITS` line covers the default reason, which carries no caveat and is the most-clicked path. Those lines also carry the `Cebab-vie.17` correction: a hop is no longer an unbounded agent turn, so "nothing stops it" would now be the wrong answer — the per-hop turn cap ends the hop and Stop ends the session, while no per-agent verb aborts a running turn.

  **A control verb now reaches the turn QUEUE, not only the router (`Cebab-vie.1` / `Cebab-vie.11`).** `AgentRunner` read an agent's control state when a delivery was ENQUEUED and never again, and a worker's turns are serialized — so "this delivery is waiting behind another one" is the ordinary state of a busy bus, and it was exactly the window in which the operator acts. **Pause** spliced its gate into `turnTails` as `prevTail.then(() => gate)`, i.e. behind everything already queued: N waiting deliveries meant N full unattended turns after the click, while the `agent_control.paused` row said paused-from-T and the echo reported those same N turns to the operator as `queuedDeliveries` — the count being held back. **Kick** was worse, because it is irreversible: a queued delivery started a brand-new tool-capable turn for a kicked worker under a UI reading "kicked", with its `bus_send` output still dropped as `kicked_source`, so the operator got drop notices and no sight of what it did. `deliverTurn` now re-reads at DEQUEUE — a loop, because a kick can land while a delivery is already parked and because pause → resume → pause installs a new gate — and refuses with `TurnRefusedError` (the fifth `isBusControlSignal` member) or waits. Two details are load-bearing: `handle.kickAgent` releases any standing hold, or a delivery parked on the pause gate the `auto_kick` path never resumes would sit there for the life of the process rather than being refused; and the routers' `.catch` returns silently on the sentinel, because the operator's row is written by the refusal itself and `onWorkerFailed` would park a Retry button for the participant they just removed. The in-flight turn still drains in both cases — that is what `mode: 'drain'` and §5.2 promise, and it is the remainder `Cebab-vie.2` tracks.

  This also corrected three UI strings that had been true only of events (`Cebab-vie.12`): the kicked pill's "will not send or receive any further bus events" (a delivered prompt is not a bus event), the controls chip's "out of the loop until the session ends", and the kick modal's silence about queued work.

  **The two operator replay seams are gated by the same state (`Cebab-vie.9`/`.10`/`.18`).** All of that enforcement lives on the path a `BusEvent` takes — which is why the kick contract could be stated as "no new turns ever start for the kicked agent: the router drops every event addressed to it before the wake". `handle.retry()` and `handle.continueThroughMutation()` are the only turn-starters that do **not** begin as an event, so none of it was structurally in their path: Retry resurrected a kicked worker with a full tool-capable turn, and Continue did the same _carrying the one-shot approval grant_, so the resurrected turn re-issued the approved `rm -rf` **pre-approved** — while its `bus_send` output was still dropped as `kicked_source`, leaving the operator with drop notices and no sight of what the worker actually did. The same two seams also ignored `ended` and the hop budget, which needs no resume dance to reach: several router paths bump the hop counter and return _before_ the budget check, so `hopsCount >= hopBudget` on a live session is an ordinary state. Both now call the router's `checkTurnRefused` first (`bus/turn_guard.ts` holds the reasons and the wording so the two routers cannot drift); a non-null answer means the turn does not start and the operator has already been told, via the same `cebab → user kind=error` channel a worker failure uses. A kicked worker's banner is resolved rather than left clickable — `consumed`, so no unspent grant survives it.

  **A run left with nobody working says so (`Cebab-vie.8`).** Muting a worker the orchestrator is waiting on drops its reply at the router — before the persist, before the deliver branch — so nothing is woken. The session row stays `running`, the hop counter stays frozen (a dropped event is deliberately "as if it never happened", so the budget brake can never fire either), and the trail's last hop is still `orchestrator → scribe prompt`. That tail is what the web activity bar reads to name the working agent, so the operator was shown `scribe working` with a timer counting past seven minutes on a session with zero live processes. The drop is not the defect and is unchanged — it is audited, it raises a danger notification, and dropping outbound events is mute's job. The defect was that Cebab then asserted the opposite of the truth, and so gave nobody a reason to reach for the recovery that existed (in orchestrator mode the prompt composer renders in exactly this state; in chain mode it does not, and Stop really is the only way out).

  So the fix is a sentence, not a routing change: `bus/quiescence.ts` decides, and each router persists a `cebab → user kind=error` row directly (bypassing `forwardCebabEvent`, so it does not count as a hop — the `onWorkerFailed` pattern). Waking the orchestrator to tell it about the drop was the alternative and is worse: it spends quota, hands a muted worker's existence back to the agent layer, and loops forever if the orchestrator re-delegates to the same muted worker.

  Two properties are load-bearing. The predicate is the **activity bar's own** — `tailAwaitsAgent` in `@cebab/shared`, called by `web/src/store.ts:activeAgent` and by the detector — so the note fires on exactly the tails that would otherwise be labelled "working", and a false positive of the note is by construction a true positive of the lie. And it is **self-limiting without a flag**: the note's own row is addressed to `user`, so the tail stops awaiting an agent the moment it exists, and it re-arms by itself if the operator sends a prompt and the run strands again. The four conjuncts (a turn still running, a torn-down session, a held queue, and the tail rule) live in one function so dropping one is a visible edit; `turn_bracket_sites.test.ts` derives from the source that each router still has exactly one `deliverTurn` call site and that it is bracketed, because "the count is complete by construction" stops being true the moment a second one appears.

## Session-log export

`GET /session-log/:sid?token=…&format=redacted|raw` is the only route that hands a session's bytes to a human. Three gates, all in `session_log_export.ts`'s header: the Origin allow-list, the Host allow-list, and the per-launch auth token; `format=raw` additionally requires `X-Cebab-Acknowledge-Raw: I-understand`, which the UI sets only behind a typed confirmation. Every successful export writes a `safety_audit` row **before** the body lands (BE-1 — if the intent cannot be recorded, the data does not ship).

**The redacted artifact's corpus is the durable message classes** (`Cebab-ygu.47`), not "the file with redaction applied". It used to be the latter, and that shipped plaintext credentials: measured on a real session, 35 KB of `format=redacted` with three canaries surviving, every one inside a `stream_event`. No additional pattern could have fixed it. `redactSensitive` masks values under sensitive key names plus a few value shapes; a delta carries free text under the key `text`, and a secret is **chopped across deltas**, so no per-line rule can match either half — the `db_password` that was masked correctly in the durable `assistant` message shipped as `horse-battery-staple-…` in the `content_block_delta` that built it. `runner/message_classes.ts` now holds the one predicate the `events` writer and the export both consult, as a **deny**-list so a new SDK type defaults to durable-and-redacted rather than silently vanishing.

The header sentence that let this through review is worth remembering: it said the export "applies LogsModal's redaction policy line-by-line". True about the policy, false about the **corpus** — the modal reads `events`, which never contained a partial — so everyone reasoning from the claimed parity concluded the export was covered. A parity claim is only as good as the corpus it is claimed over.

**A credential-NAMED assignment inside free text is masked, and that class was measured as empty by accident** (`Cebab-ygu.51`). `Cebab-ygu.47` recorded "leaks OUTSIDE `stream_event`: NONE" from the same real session. True of that file, and not a property: the durable `assistant` / `user` / `result` copies were masked because each of those strings ALSO carried an AKIA key, and `walk()` replaces the whole string when any value pattern hits. Remove the unrelated secret and the marker walks out. So `redactSensitive` now reads the string for `name = value` where the NAME matches its own key list — the same `isSensitiveKey` the env-injection gate shares, not a second vocabulary — and masks the VALUE SPAN, leaving the prose and the key name readable.

The bead had left this open as "an over-masking policy call", and that framing was about WHOLE-STRING masking. Measured against 24 real session transcripts (4390 lines) by diffing the redactor's output against its own previous output: **4 lines masked more, on 2 distinct spans**, both `session_id: sessionId` inside a `Read` of Cebab's own `ws/server.ts`. The generic alternative that was rejected — any 32+ character mixed-case-and-digit token, i.e. entropy with no key name — masks **1544 spans** on the same corpus (session ids, base64 blobs, hashes). That is the cliff the warning was about, and it is why the rule is keyed on the name and nothing else.

**The residue is real and named.** A value with neither a credential-shaped key nor a credential-shaped value — `plain_marker = <secret>` — is indistinguishable from prose and still ships. It is pinned as a known limit in `redact.test.ts` beside the 1544, so the next reader meets the number before the idea.

**An unparsable line records its own existence, not its bytes.** The export used to pass non-JSON through verbatim, reasoned as not losing forensic data. The reasoning holds; the conclusion was a bypass, because a class rule only sees lines that parse and `runner/logger.ts` appends with no coordination against readers — so exporting a live session routinely observes a torn final line, and a torn delta went through with its text intact. The fact and the byte count survive as a `cebab_unparsable_line` placeholder.

**The audit row attests intent and policy; the artifact attests itself.** `payload.contentPolicy` names the code path that produced the bytes, so a row written by the leaky build is distinguishable from one written after the fix — the bead's sharpest point was that the chain asserted `exported_redacted` over a file holding plaintext. It is deliberately not a measurement: the row precedes the body, so nothing about the emitted bytes is knowable yet, and a count of what was removed attests nothing about what remains.

**Two honest costs, stated here because the export's users need them.** A partial with no durable counterpart — a turn killed by `interrupt()`, an abandoned tool input — is not in the redacted artifact. And `format=raw` is reachable by curl only: both UI call sites hardcode `redacted`, so the operator's route to the complete trace is reading `~/.cebab/logs/<sid>.jsonl` directly (same machine, same uid, mode 0600), not a button.

## Browser threat model

The WS upgrade is gated on `Origin` and `Host`: the browser must come from `http://127.0.0.1:5173` (Vite dev) / `http://localhost:5173` / `http://127.0.0.1:$PORT` / `http://localhost:$PORT`. Extra origins via `CEBAB_ALLOWED_ORIGINS` (comma-separated). Empty `Origin` is allowed — browsers always set it on WS upgrades, so an absent header means a non-browser client (smoke tests, curl), and the server is bound to 127.0.0.1 anyway. Without the Origin check, any tab the user has open could connect to the local server (Cross-Site WebSocket Hijacking).

## Per-launch auth token

**A per-launch token shipped** (`server/src/auth.ts`) — an earlier version of this file said such tokens were out of scope for v1, and someone hardening the socket gate on that basis could have removed a live control. Cebab generates the token once at boot, writes it to `~/.cebab/auth-token` (mode 0600), serves it from the Origin+Host-gated `/auth-token` endpoint, and the WS `verifyClient` gate rejects any upgrade whose `?token=` doesn't match. It closes browser-tab CSWSH (a cross-origin tab can't pass the Origin gate to fetch the token) and, on POSIX, other local users. It does **not** close same-uid: a bus agent runs as the operator, so it can read the token off disk and open its own connection — there is no boundary to build there, which is why the posture is **detect, not prevent** and the control-plane verbs are hardened individually instead. `server/src/auth.ts`'s header is the full statement.
